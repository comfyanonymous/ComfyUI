## Pyro's Prompting Philosophy

**T5 Encoder Understanding:**

Unlike SDXL's CLIP, FLUX uses T5 which is very literal:
- Don't repeat concepts (e.g., "woman" twice, "penis" twice)
- Use simple, clear descriptions
- Both tags and natural language work (1-2% difference)
- Don't overload with unnecessary details

**Good prompt:** `a woman sucking a penis`
**Bad prompt:** `pov, 1girl, penis, blowjob, cleavage, kneeling, a woman kneeling in front of a man sucking his huge cock`

**Why simple is better:**
- T5 builds its own understanding
- Overloading causes concept bricking
- Model learns wrong associations from repeated tags

## Technical Notes from Pyro

### Why SDXL Captioning Fails on FLUX

- FLUX uses T5 encoder (not just CLIP like SDXL)
- T5 is very literal in interpretation
- SDXL-style tag overloading causes model bricking
- Bricking = model freezes, loses ability to learn
- Once bricked, training is unrecoverable

### Dataset Quality Philosophy

- Facial feature extraction and clustering for bias detection
- 50k pairs of eyes analyzed for diversity
- Every feature that causes bias is identified before training
- No shortcuts like WD14 tagger + basic scraping

### Same-Face Syndrome Causes

1. **Dataset bias** - Certain face appears more than others
2. **Over-merging** - Averaging face concepts to death
3. **Even base FLUX.dev** has same-face issues (lips, head shapes)
